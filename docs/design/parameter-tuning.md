# 请求参数调优设计

> 状态:参数校验、插件存储、请求前补丁与宿主设置表面已接入(见第六节);JSON 导入入口保留为兼容路径。
> 本文记录机制与取舍理由,规范与 Schema 见 [specs/README.md](../../specs/README.md);两者冲突时以规范为准。

## 一、定位与边界

dsc-llm-tune 让用户直接设定 LLM 请求的常规参数:温度、top_p、max_tokens 与停止词。插件不理解场景,也不替用户做选择:用户给什么值,插件就把什么值放进请求补丁;用户没给值,插件不改请求。

| 做 | 不做 |
|:---:|:---:|
| 激活期向宿主登记设置字段描述,由宿主渲染设置表单(见第六节) | 不提供预设:不内置推荐值、不按场景或意图切换参数 |
| 每次发请求前把设置页取值与导入参数按优先级合并成宿主补丁 | 不改系统提示词:提示词的追加与替换属于 dsc-humanize |
| 保留一条 JSON 文本导入入口,作为兼容路径与批量粘贴通道 | 不做多套参数、按会话覆盖或按模型区分 |
| 导入时按宿主补丁的边界一次校验,越界直接拒绝 | 不在请求前重复校验或裁剪,越界值到不了补丁层 |

三条边界值得单独说明:

- 不提供预设:预设意味着插件替用户判断「什么场景该用什么参数」,这正是 dsc-humanize 在做的事,重复会变成两套互相矛盾的推荐。
- 不改提示词:宿主补丁里虽然有 `systemPromptAppend` 与 `systemPromptReplace`,但提示词是 dsc-humanize 的领域,本插件只碰采样参数与停止词,两者职责不交叉。
- 不做自动决策:插件在请求前不读最后一条用户消息,也不按会话状态分支;处理器只做字段拷贝,结果可预测。

## 二、与 dsc-humanize 的互斥

两个插件都申请 `chat:request` 能力、都声明 `chat:before-request` 挂载点,都要改写同一次请求的采样参数,因此互斥。

| 项 | dsc-humanize | dsc-llm-tune |
|:---:|:---:|:---:|
| 参数来源 | 资产包里的策略表,按意图分类后解析 | 用户直接设定的一份参数文档 |
| 决定方式 | 按最后一条用户消息分类,命中标签后用策略 | 不分类、不看消息,恒定用当前设定 |
| 输出 | 采样参数、停止词与系统提示词追加 | 只输出采样参数与停止词 |
| 互斥声明 | 需在其清单里写 `dsc-llm-tune` | 本插件清单写 `conflicts: ['dsc-humanize']` |

为什么必须是互斥而不是共存:

- 多个插件同时登记请求前处理器时,引擎按登记顺序合并补丁:标量字段以后登记者为准,`stop` 取并集并在 4 条处截断,`systemPromptAppend` 按顺序拼接。两个插件都在决定 `temperature` 这类标量时,最终生效的是后登记者,顺序取决于激活顺序,用户无法从界面上判断实际取值。
- 两者的参数语义也不同:humanize 的取值来自策略表,本插件的取值来自用户输入;同时开启时,用户以为自己在设定参数,实际可能被策略表覆盖。
- 因此按「同时安装即拒绝」处理:清单里的 `conflicts` 由宿主在安装阶段判定,两个插件不可能同时处于已安装状态,也就不存在合并顺序问题。

互斥声明是双向的,两侧各写自己这一份:

| 一侧 | 位置 | 状态 |
|:---:|:---:|:---:|
| 本插件 | [src/manifest.ts](../../src/manifest.ts) 的 `conflicts` | 已写 `dsc-humanize` |
| dsc-humanize | 其仓库的 `src/manifest.ts` 的 `conflicts` | 由 dsc-humanize 仓库负责,本仓库不改动 |

互斥只作用于安装阶段:宿主按清单的 `conflicts` 判定「同时安装会被拒绝」。停用一个插件但保留安装是否算共存,取决于宿主对 `conflicts` 的判定时机;本插件不假设停用状态能绕开互斥,也不提供绕过路径。

两者互补的地方不在同一次请求里:humanize 负责助手形态与提示词,本插件负责采样参数。需要两个能力时,用户按当前任务在两者之间切换,而不是同时开启。

## 三、参数集合

参数集合固定为四项,与宿主补丁的白名单字段一一对应,不做无效字段的透传:

| 参数 | 文档字段 | 取值 | 宿主补丁字段 | 处理 |
|:---:|:---:|:---:|:---:|:---:|
| 温度 | `temperature` | 0 到 2 的数字 | `temperature` | 越界拒绝,不裁剪 |
| top_p | `topP` | 0 到 1 的数字 | `topP` | 越界拒绝,不裁剪 |
| max_tokens | `maxTokens` | 1 到 4096 的整数 | `maxTokens` | 非整数或越界拒绝 |
| 停止词 | `stop` | 最多 4 条,每条最多 32 个字符 | `stop` | 空串、超长、完全重复按规则处理,见下 |

规则细节:

- 四个字段全部可缺省:缺省的字段不进补丁,请求里的对应项保持宿主的原值。四项都不给时补丁为空,处理器返回 `null`。
- 数值与长度的边界与宿主补丁的边界一致,导入时一次校验。超界不是「裁剪后生效」而是「整份拒绝」:用户写错了值应该看到错误,而不是拿到一个被悄悄改过的结果。
- 停止词按原样保留,不去首尾空白:停止词经常就是换行、空格这类有意义的空白串,去空白会把用户要的串改坏。只拒绝空字符串、超过 32 个字符的条目与完全重复的条目,重复项保留第一份。
- `stop` 给空数组等同于没给,不进补丁;这与宿主「空白字符串按未提供处理」的口径一致。
- 不使用 `systemPromptAppend` 与 `systemPromptReplace`:见第一节的边界说明。

## 四、参数文档与插件存储

参数以「一份文档」的形式整体存放,不做增量写入,便于整份替换与整份清除。

### 4.1 存储位置

| 项 | 取值 |
|:---:|:---:|
| 存储能力 | `plugins:storage`(`context.storage`) |
| 键名 | `dsc-llm-tune/params/v1` |
| 值 | 参数文档对象,可 JSON 序列化 |
| 容量 | 单插件 64KB 上限,参数文档只有几百字节 |

键名带版本号:文档形状变化时换新键,旧键里的值按不支持处理,由下一版决定是迁移还是丢弃。

### 4.2 文档形状

```json
{
  "paramsVersion": 1,
  "temperature": 0.7,
  "topP": 0.9,
  "maxTokens": 2048,
  "stop": ["\n\nUser:"]
}
```

| 字段 | 必填 | 说明 |
|:---:|:---:|:---:|
| `paramsVersion` | 是 | 固定为 `1`,其他取值按 `unsupported-version` 拒绝 |
| `temperature` | 否 | 0 到 2 的数字 |
| `topP` | 否 | 0 到 1 的数字 |
| `maxTokens` | 否 | 1 到 4096 的整数 |
| `stop` | 否 | 字符串数组,最多 4 条,每条最多 32 个字符 |

- 顶层只允许上表五个字段,名字写错(例如写成 `top_p` 或 `max_tokens`)按 `invalid-parameters` 拒绝。拒绝而不是静默丢弃,是因为「写错了却看起来生效」比直接报错更难排查。
- 任一字段不合法都整份拒绝,不做部分保留;用户改好一次再导入即可。

### 4.3 读取、导入与清除

三条路径共用一个校验函数,结果只有「可用」与「不可用」两种:

| 路径 | 触发 | 行为 |
|:---:|:---:|:---:|
| 读取 | 插件激活时 | 从存储取文档,合法才装配;缺失、版本不符、字段非法都保持未设定,请求按原样发出 |
| 导入 | 用户交来一份 JSON 文本 | 解析、校验,成功才替换当前参数;已激活时同时写回存储 |
| 清除 | 用户主动清除 | 内存里的参数立即清空;已激活时删除存储里的文档 |

- 读取失败不阻断激活:参数是增强项,读不到就当没设定,插件其余部分照常工作,失败原因写进插件日志。
- 导入成功但写入存储失败时,内存里的参数仍然生效,只把「是否已持久化」置为否并写日志:请求已经能按新参数改写,没必要因为存储问题回滚。
- 未激活时导入只装配到内存,下一次激活以存储为准;这是为了让导入在插件面板外也能调试。

### 4.4 键名与形状的稳定性

键名 `dsc-llm-tune/params/v1` 与文档形状不再变动:宿主设置表面接入后,这份存储只承载导入路径的参数,设置页的取值由宿主的设置命名空间管理(`settings/<pluginId>/<fieldKey>`,与 `plugins:storage` 的插件数据完全分开),两份数据互不迁移。导入入口是长期保留的兼容路径,不是待淘汰的过渡品,因此键名与文档形状按长期契约维护。

## 五、请求前补丁

处理器在每次发请求前被同步调用一次,全部处理器共用 10 毫秒预算,因此这一层只做字段拷贝:

| 项 | 约定 |
|:---:|:---:|
| 输入 | 请求切片 `preview`,本插件不使用其中任何字段 |
| 取值 | 处理器入口先 `context.settings.values()` 读设置页实时值,再与导入层参数按 6.3 的优先级合并(`resolveParameters`) |
| 输出 | 补丁对象;没有设定时返回 `null`(什么都不返回等价) |
| 耗时 | 一次同步读值、一次合并与字段拷贝,不做 IO、不做解析 |
| 异常 | 读设置值抛错回落导入值并写日志;本插件不主动抛错,即使抛错,引擎也会整份作废补丁并让请求按原参数发出 |
| 落地 | 引擎按白名单收敛补丁,越界值按边界裁剪;本插件的取值已在入口期落在边界内 |

- 补丁只影响之后的请求,已经发出的请求不受影响。
- 参数与用户消息无关,处理器不读 `preview.lastUserMessage`:同样设定在任何会话、任何消息下都得到同样的补丁。
- 将来若出现多个插件同时改写采样参数的情形(例如用户装了同类第三方插件),合并规则仍由引擎决定(标量后写者覆盖、`stop` 求并集)。本插件不参与协商,也不做规避。

## 六、参数设定入口:已接入宿主设置表面

### 6.1 现状

宿主已落地插件设置表面(settings:surface):插件在清单里申请能力 `settings:surface`,激活期用 `context.settings.register(descriptor)` 登记一份字段描述,宿主据此渲染设置表单;用户在表单里改值并保存,覆盖值落在宿主的设置命名空间(`settings/<pluginId>/<fieldKey>`),与 `plugins:storage` 的插件数据完全分开。插件只交描述、不交控件:控件形态、样式与渲染全部归宿主,插件读自身取值用 `context.settings.values()`(同步,覆盖值优先,否则登记默认值)。

清单因此新增两项申请:`settings:surface`(登记与读值)与 `settings:locale`(读宿主语言,给字段标签选词,见 6.4)。

### 6.2 登记的字段描述

| 字段键 | 类型 | 取值范围 | 登记默认值 | 标签(zh / en) |
|:---:|:---:|:---:|:---:|:---:|
| `enabled` | switch | 开 / 关 | 关 | 启用设置页参数 / Use settings page values |
| `temperature` | number | 0 到 2,步进 0.1 | `1` | 温度 temperature(0 到 2) / Temperature (0 to 2) |
| `topP` | number | 0 到 1,步进 0.01 | `1` | top_p(0 到 1) / top_p (0 to 1) |
| `maxTokens` | number | 1 到 4096,步进 1 | `4096` | 最大生成 token 数(1 到 4096) / Max tokens (1 to 4096) |
| `stop` | text | 最多 200 字符 | `""`(留空) | 停止词,逗号分隔(最多 4 条) / Stop sequences, comma separated (up to 4) |

- 数值边界与参数校验层(`src/tuning/params.ts`)共用同一组常量,两侧不会各自漂移;宿主写侧按 min/max 校验,越界值写不进设置表。
- 登记默认值不是预设:引擎要求非 secret 字段必须给 default,而本插件不提供预设,三个数值取 DeepSeek API 的默认口径,开关默认关、停止词默认留空。默认值在请求前只承担「未被用户改动」的哨兵职责,见 6.3;用户不改字段,默认值就不会进补丁。
- 设置页里停止词是一个逗号分隔的文本框:按逗号切分、每条去首尾空白、空条目丢弃、重复项保留第一份;超过 4 条或某条超过 32 个字符时该字段按未设定处理。要保留空白字符的停止词(例如换行、空格串),请走导入入口,那里的数组形状按原样保留。
- 宿主过旧没有 `settings` 成员、语言读取或登记失败时都不阻断激活:参数回落导入入口,失败原因写插件日志。

### 6.3 取值优先级

请求前处理器每次请求都读一次 `context.settings.values()`,把设置页取值与导入层参数按逐字段优先级合并,规则实现在 `src/host/settings.ts` 的 `resolveParameters`:

| 优先级 | 条件 | 结果 |
|:---:|:---:|:---:|
| 1 | 总开关 `enabled` 打开,且该字段的生效值不等于登记默认值(即用户在设置页改过) | 以设置页取值为准 |
| 2 | 该字段设置页没有覆盖值(开关关闭、未改动、取值非法或停止词文本不合法) | 回落导入层参数(存储读取或 `importParameters` 交付的那一份) |
| 3 | 两侧都没有 | 该字段不进补丁;四个字段都没有时处理器返回 `null`,请求保持原样 |

这条优先级的三个设计点:

- 逐字段判定而不是整页接管:设置页只改了温度时,其余字段仍走导入参数,两个入口可以在一份配置里各管几个字段;这也是「不做预设」的自然延伸,没改过的字段不应该悄悄带上登记默认值。
- 「设置覆盖值」的判定依据是「生效值不等于登记默认值」:`context.settings.values()` 只给生效值,不给覆盖标志,等于默认值即按未改动处理。已知取舍:用户把某字段刻意改成与登记默认值完全相同的取值时,插件无法与「没改过」区分,该字段回落导入值;由于默认值取 API 默认口径,两种情况的实际效果通常一致。
- 总开关 `enabled` 关闭(默认)时设置页整体不参与,参数完全由导入路径决定:只导入不碰设置页的老用户,行为与设置表面接入前一致,这是导入入口保持兼容的前提。读取设置值抛错(例如触发限流)同样回落导入值并写日志,不阻断请求。

### 6.4 字段标签的 i18n

设置表面的标签只能二选一:`labelKey` 必须是宿主 i18n 字典里已有的键,插件不能往字典里加键;`label` 是插件直给的文案,不分语言。本插件选 `label` 并自行配对词条:`src/host/settings.ts` 里维护一张 zh/en 成对的标签表,激活期先 `await context.settings.locale()` 读宿主语言,再按语言取一侧登记。

已知限制:标签按激活时的宿主语言定型,激活后切换宿主语言,已登记的标签不会跟着换,需要停用再启用(重新激活)插件;宿主 i18n 字典开放插件词条后可以换成 `labelKey`,届时删除这张表即可。

### 6.5 导入路径(保留的兼容入口)

导入入口 `importParameters(jsonText)` 与清除入口 `clearParameters()` 原样保留,读取导入层当前值用 `getActiveParameters()`;导入成功即替换导入层参数,已激活时写回插件存储,持久化行为见第四节。适合的场景:

| 场景 | 为什么走导入而不是设置页 |
|:---:|:---:|
| 保留空白字符的停止词 | 设置页的逗号分隔文本框会去掉条目首尾空白,导入的数组按原样保留 |
| 批量粘贴一份完整参数 | 一次粘贴整份文档,设置页要逐字段点改 |
| 调试与自动化 | 导入函数可直接调用并拿到结构化错误(`code` 与字段 `path`),不依赖界面 |

导入值只在设置页没有覆盖值的字段上生效(见 6.3),两条路径不冲突。

## 七、已排除做法

| 做法 | 排除理由 |
|:---:|:---:|
| 内置预设与场景模板 | 与「用户直接调参数、不提供预设」的定位冲突,也会与 dsc-humanize 的策略表重复;登记默认值只作「未改动」哨兵,不进补丁 |
| 按意图或关键词自动选参数 | 与 dsc-humanize 的职责重叠,且让结果不可预测 |
| 插件自建浮层界面 | 直接操作宿主 DOM 属于绕过引擎;界面应由宿主的设置表面提供,现已接入 |
| 请求前再做一次校验或裁剪 | 引擎已按边界裁剪,重复校验只增加 10 毫秒预算的压力;导入与设置页两侧的取值都在入口期校验 |
| 直接用 `localStorage` 读写 | 绕过 `plugins:storage` 的能力边界,违反插件契约,也不会随插件卸载清理 |
| 与 dsc-humanize 共存并靠合并顺序决胜负 | 用户无法预测最终取值,调试成本高于收益 |
| 按字段忽略「等于登记默认值」之外的改动检测手段 | `context.settings.values()` 不给覆盖标志,插件侧没有更可靠的判定依据;改用整页接管会让未改字段悄悄带上默认值 |

## 八、与 dsc-inner-plugin 的关系

本插件最终由 dsc-inner-plugin 收录,收录前需要核对三件事:

| 项 | 要求 |
|:---:|:---:|
| 产物 | `dist/` 整目录交付,`meta.json` 的 `name` 与合集索引一致 |
| 互斥声明 | 本插件已声明 `conflicts: ['dsc-humanize']`;dsc-humanize 侧需声明 `dsc-llm-tune`,两处同时成立才算双向互斥 |
| 状态披露 | 收录说明里要写明:参数在宿主插件详情页的设置表单里设定(总开关默认关),导入入口作为兼容路径保留;宿主过旧时只有导入路径可用 |
